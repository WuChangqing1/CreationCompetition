# 00 项目结构说明

## 一句话理解

这个项目先把原始音频、视频和受试者描述变成 `.npy` 特征，再由 Dataset 对齐并补齐序列，最后交给完整模型训练或测试。`models/networks` 像零件箱，`models/*_model.py` 才是能直接参加实验的整机。

## 关键目录

- `config.json`：OurModel 的网络维度、分类层、损失权重、优化器和输出位置。
- `dataset.py`：读取音频/视觉 `.npy`、personality embedding 与标签，输出统一字典。
- `feature_extraction/`：离线特征提取。音频支持 MFCC/OpenSmile/wav2vec，视觉支持 DenseNet/ResNet/OpenFace，个性化特征来自描述 embedding。
- `models/networks/`：LSTM、全连接、分类器、自注意力等组件。组件本身通常不包含训练损失和优化器，不等于完整模型。
- `models/our/`：原项目的完整 OurModel/BiCFNet。
- `models/__init__.py`：PyTorch 完整模型动态入口。
- `train.py`：兼容旧命令的单次训练入口。
- `test.py`：checkpoint 推理、ensemble、subject voting 与提交文件入口。
- `train_val_split.py`：旧训练/验证划分；新 5-Fold 不使用它生成对比 folds。
- `experiments/`：新多模型调度、固定 folds、评估、效率、结果和 smoke test。
- `scripts/`：旧 Track1/Track2 Shell 命令，保留不删。
- `checkpoints/`：历史权重；新 checkpoint 会增加可复现元数据。
- `logs/`：历史训练日志与 CSV。
- `docs/`：中文说明、稳定上下文与当前开发状态。

## 数据流

```text
Raw Audio/Video
  → feature_extraction
  → MFCC/DenseNet 等 .npy
  → AudioVisualDataset 对齐、补齐、标签与 personality
  → DataLoader batch
  → models.create_model() 创建的完整 PyTorch 模型
  → logits / probability / loss / checkpoint / metrics
```

训练时不会重新训练音频或视觉 backbone；模型消费的是预提取特征。

## Track 与任务兼容

新实验框架默认聚焦 Track1 Elderly Binary，但原 Track2、三分类、五分类入口和脚本会保留。默认聚焦不等于删除旧能力。
